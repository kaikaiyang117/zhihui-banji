# 开发、验证与发布流程

本文档记录当前项目的标准工作流：本地开发、自动验证、桌面打包和 GitHub Release。

## 1. 日常开发

### 1.1 准备环境

macOS/Linux：

```bash
./scripts/setup-dev.sh
```

Windows PowerShell：

```powershell
.\scripts\setup-dev.ps1
```

要求：Python 3.11+、Node.js 20+。运行桌面安装包不需要 Python 和 Node.js；只有源码开发和前端构建需要它们。

### 1.2 启动源码版本

```bash
./启动工作台.command       # macOS
```

Windows 直接双击 `启动工作台.bat`。源码启动默认开启局域网访问，电脑、手机和平板连接同一 Wi-Fi 后，可以在工作台右上角扫描“手机访问”二维码。

源码启动使用项目根目录的 `data/` 和 `知识库/`，不要把生产数据目录和临时测试数据混用。

### 1.3 分支和提交

从最新 `main` 创建开发分支：

```bash
git switch main
git pull --ff-only origin main
git switch -c codex/<feature-name>
```

完成修改后先验证，再提交和推送：

```bash
git diff --check
git add <相关文件>
git commit -m "feat: <简短说明>"
git push -u origin codex/<feature-name>
```

开发分支合并到 `main` 后，再从 `main` 创建发布标签。

## 2. 本地验证

后端测试使用隔离 SQLite 数据，不会修改正式数据库：

```bash
python -m unittest discover -s backend/tests -p 'test_*.py' -v
```

前端构建：

```bash
cd frontend
npm run build
cd ..
```

浏览器冒烟测试：

```bash
bash scripts/smoke-ui.sh
```

冒烟测试会启动临时后端，检查首页、二维码入口和更新入口，结束后自动清理临时数据。

## 3. 本地打包

先构建前端并安装 PyInstaller：

```bash
cd frontend && npm run build
cd ..
python -m pip install pyinstaller
```

macOS：

```bash
./packaging/build-macos.sh arm64    # Apple Silicon
./packaging/build-macos.sh x86_64   # Intel
```

Windows PowerShell：

```powershell
.\packaging\build-windows.ps1
```

安装包输出在 `artifacts/`。本地没有证书时，打包脚本会生成未签名包并给出提示；这不影响功能验证。

## 4. GitHub Actions

当前仓库有两条主要流水线：

| 触发方式 | 流水线行为 |
|---|---|
| 推送 `main` 或 `codex/**` | 后端测试、前端构建、Playwright UI 冒烟测试 |
| 创建/推送 `v*` 标签 | 构建 Windows x64、macOS arm64、macOS x86_64，并创建 Release |
| Actions 页面手动运行 `Build desktop releases` | 只构建并上传 Artifacts，不创建 Release |

正式发布：

```bash
git switch main
git pull --ff-only origin main
git tag -a v1.0.5 -m "美美大王工作台 v1.0.5"
git push origin v1.0.5
```

标签发布成功后，Release 页面应包含：

- `MeimeiWorkbench-Setup-Windows-x64.exe`
- `MeimeiWorkbench-macOS-arm64.dmg`
- `MeimeiWorkbench-macOS-x86_64.dmg`
- `SHA256SUMS.txt`
- `update-manifest.json`

当前可参考发布版本：[v1.0.4](https://github.com/aitia0718/workbench/releases/tag/v1.0.4)。

## 5. 签名和安全状态

代码签名不是构建的前置条件。没有配置证书时，流水线仍会发布未签名安装包，并在 Release 说明中标注：

- Windows：未签名，可能出现 SmartScreen 提示。
- macOS：未签名、未公证，可能需要在系统设置中手动允许打开。

如果以后需要正式对外分发，再在 GitHub Repository Secrets 中配置 Windows 和 Apple 凭证。不要把 `.pfx`、`.p12`、证书密码或 Apple App 专用密码提交到仓库或发送到聊天中。

## 6. 发布后检查

1. 打开 Release 页面确认三个安装包和两个校验文件都存在。
2. 下载并核对 `SHA256SUMS.txt`。
3. 在至少一台实际设备上安装并启动。
4. 电脑与手机连接同一 Wi-Fi，扫描二维码访问。
5. 在桌面安装包中点击“更新”，确认下载、SHA-256 校验和安装流程正常。
6. 升级前后确认数据库、备份和知识库仍然存在。

详细清单见 [`docs/发布检查清单.md`](发布检查清单.md)。

## 7. 常见故障

### 端口被占用

程序会从 5000 开始自动寻找可用端口，并在终端打印实际端口。手机二维码会使用实际端口，不需要手动修改网址。

### 手机无法访问

确认手机和电脑在同一 Wi-Fi，允许应用通过电脑防火墙的专用网络，并使用电脑端刚生成的二维码。二维码只能使用一次且 5 分钟后失效；已授权设备重启程序后仍可使用，被撤权或主动退出后需要重新配对。

### Release 构建失败

先查看失败的具体 Job：源码验证、平台构建、签名、更新清单和 Release 发布是不同阶段。修复后使用新的补丁版本标签，不要移动已经推送的旧标签。
