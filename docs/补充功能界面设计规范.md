# 补充功能界面设计与验收规范

> 用途：约束 `docs/补充功能讨论清单.md` 中各工作包的入口、信息架构、交互状态、响应式布局和视觉验收。
>
> 适用范围：`SUP-01` 至 `SUP-09` 的网页、局域网手机页面、微信 iLink 消息界面和 Electron 桌面宠物。
>
> 视觉权威：颜色、字体、圆角、间距、材质和动效以根目录 `DESIGN.md` 为准；实际 token 和共享组件以 `frontend/src/styles/`、`frontend/src/components/` 为准。本文件不复制这些值，只规定新增功能如何组合它们。

## 0. Agent 使用方式

### 0.1 开始 UI 工作前

开发 Agent 必须按顺序完成：

1. 阅读 `DESIGN.md`、本文件和对应 `SUP-xx` 工作包。
2. 定位现有路由、导航、API、最近似页面和可复用组件；至少查看一个真实页面实现，不能只看截图重新造一套样式。
3. 在任务说明中写出“界面合同”：入口、主要用户、首要动作、信息顺序、写入副作用、桌面/手机布局和必须覆盖的状态。
4. 确认新增入口不会与现有导航、首页快捷入口或 Agent 浮窗重复。
5. 只有上述内容清楚且与业务服务契约一致后，才开始写 Vue/Electron 代码。

完成条件：任务说明能够让另一名 Agent 不看实现代码，也能画出相同的信息结构和主流程；如果不同 Agent 仍可能画出两套完全不同的入口，界面合同尚未完成。

### 0.2 实现顺序

1. 先接真实 API 和路由，确认主流程能跑通。
2. 再完成加载、空数据、错误、只读、权限和重复提交状态。
3. 再完成桌面和手机布局。
4. 最后补充动效、微交互和视觉精修。

不得先做一个只有静态假数据的漂亮页面，再倒推业务服务和权限。设计稿中的示例文案不是业务事实来源。

### 0.3 角色与渠道合同

本批次的首要体验对象是“高中政治老师兼班主任”。界面示例可以使用政治课、多个年级班级、班级通知和家长会准备等语境，但组件、字段和权限必须保持学科无关。任课教师与班主任看到的内容由班级/学期授权决定，不由前端写死为某一学科。

渠道职责固定如下：

| 渠道 | 适合承载的内容 | 界面边界 |
|---|---|---|
| 桌面网页 | 完整查询、表单、表格、预览、错误行和证据管理 | 业务基线；所有写入流程必须可在此核对 |
| 手机网页 | 现场点名、查寝、拍照/截图上传、短表单和结果确认 | 单栏、分步、可触控；复杂映射和长表格回到桌面网页 |
| 微信 iLink | 短指令、班级选择、异常补充、预览摘要和确认 | 不承载完整表格；文件能力必须先通过真实协议 fixture 验证 |
| Electron 桌面宠物 | 处理中、等待确认、成功、失败和轻提醒状态 | 不承载业务数据、写入确认或第二套聊天入口 |

“所有渠道都可以考虑”表示允许按上述职责设计，不表示每个工作包首版都要四端同时完成。任务说明必须明确本次实际交付渠道和未覆盖渠道。

### 0.4 UI 完成定义

一个页面只有同时满足以下条件才算完成：

- 首要动作在进入页面后可识别，不需要从多个同权按钮中猜测。
- 正常、加载、空、校验失败、服务失败、无权限、只读/归档和提交中状态均有确定表现。
- 桌面、窄桌面和手机尺寸均没有遮挡、无法触达的按钮或意外横向滚动。
- 键盘、鼠标和触控均能完成主流程；焦点、标签和状态不只依赖颜色。
- 敏感写入先预览再确认，成功后展示实际结果，失败时保留用户已填写内容。
- 页面使用现有 token、按钮、输入、弹窗和错误反馈模式，没有新增一套近似设计系统。
- 按本文第 5 节完成截图和真实交互验证，并记录结果。

## 1. 全局界面原则

### 1.1 使用模式

本项目属于长期使用的 **Operate** 工作界面。设计优先级固定为：

1. 当前要做什么。
2. 处理对象和数据范围是否正确。
3. 操作会产生什么结果。
4. 历史和支撑信息在哪里查看。
5. 品牌与愉悦感。

愉悦感来自可靠反馈、清楚层级和“美美”角色，不用装饰压过业务信息。

### 1.2 页面信息顺序

完整业务页面默认按以下顺序组织：

1. 页面标题、用途说明和一个主操作。
2. 当前班级/学期/日期/教师等范围。
3. 今日优先事项或当前流程步骤。
4. 主内容区。
5. 历史、说明、来源和次要操作。

只有独立操作、独立滚动或需要明确边界的区域才使用卡片。相关字段优先靠邻近、标题和间距分组，避免“每个字段一张卡”。

### 1.3 入口与导航

- 首页只承载当天需要看见的摘要和一个明确跳转，不复制完整管理页面。
- 已有业务页面优先通过页内标签、分段控制或详情区域扩展；只有确实独立、高频且不能归入现有页面的能力才新增侧边栏入口。
- `SUP-05` 是外部网站和软件的唯一入口；其他页面不重复维护外链。
- Agent 浮窗用于短问答和快速动作，复杂预览、映射表和长错误列表进入 `/agent` 完整页面。
- 一个功能不能同时在首页、侧边栏、顶部标签和业务页面各放一套同等入口。

本批次允许的导航变化：

- `SUP-05` 可新增一个“工作入口”侧边栏项。
- `SUP-04` 优先进入现有课程表的“单班课表 / 我的安排”页内视图，不先新增侧边栏项。
- `SUP-06`、`SUP-07` 进入现有“家校沟通”页面的二级视图，不新增两个侧边栏项。
- `SUP-08` 嵌入相关记录详情，不新增“证据中心”导航。
- `SUP-09` 从设置和托盘管理，不进入教师业务导航。

### 1.4 工作台外壳与首页容量

首页是“今天要处理什么”的工作台，不是所有模块的总目录。实现 Agent 必须先在现有外壳上扩展，保持下面的信息层级：

1. 顶部：业务日期、当前班级/学期上下文、全局 Agent 入口和一个当天主操作（例如“开始点名”）。
2. 第一屏：行动摘要、今日课程和近期考试；考试倒计时放在今日课程附近的独立卡片，不挤占行动摘要的等宽卡位。
3. 中段：待处理工作、校历/近期安排、家校沟通或证据缺口等已有模块，按当前数据是否需要处理排序。
4. 末段：班级概况、近期活动和历史入口等低频信息。

新增功能只能提供一个最相关的跳转，不能在首页复制完整管理表格。首页新增卡片前，任务说明必须写明它替换、复用或邻接哪个现有卡片，以及空数据时如何收缩；不允许因为“以后可能有用”预留一排空卡片。

桌面端允许多栏，手机端按“今日主操作 → 今日课程/考试 → 待处理事项”顺序单栏堆叠。侧边栏、Agent 浮窗、固定底部操作和桌面宠物共同出现时，必须先做遮挡检查；业务按钮优先级高于装饰和宠物气泡。

### 1.5 主次操作

- 一个页面标题栏最多一个实色主按钮。
- 次要操作使用描边按钮或“更多操作”，危险操作与普通操作分组。
- 保存、提交、导入、写入、删除和发送类动作必须明确动词和对象，例如“确认导入 36 名学生”，不用模糊的“确定”。
- 提交中禁用重复点击并显示进行状态；成功后显示写入数量或具体对象，不只显示“成功”。
- 取消始终可见；关闭弹窗、按 Esc 和点击遮罩的行为保持一致。存在未保存内容时先提醒。

### 1.6 文案

- 使用教师熟悉的“班级、学期、学生、请假、考勤、家长、考试”等业务词，不用模型或数据库术语。
- 错误提示采用“发生了什么 + 哪些内容未保存/未写入 + 可以怎么做”。
- 空状态说明为何为空，并只提供一个最相关的下一步。
- AI 生成内容标注为“草稿”或“建议”，事实数据标注来源和时间范围。
- 隐私提示具体指出不要上传或发送什么，不使用泛化的“注意安全”。

## 2. 必须覆盖的界面状态

| 状态 | 页面要求 | 禁止表现 |
|---|---|---|
| 首次加载 | 保留页面骨架或清楚的加载提示；主操作在依赖数据未就绪时禁用 | 整页闪白、按钮仍可提交 |
| 空数据 | 说明当前范围无数据，并提供导入、创建或切换范围中的一个主要动作 | 只有“暂无数据” |
| 有数据 | 首要信息优先，次要字段可展开；长列表有筛选或分页/限制 | 把所有字段同时铺满 |
| 表单校验失败 | 错误靠近字段，同时保留顶部摘要；焦点移动到第一个错误 | 清空表单、只弹系统 alert |
| 服务失败 | 保留用户输入，说明没有写入；支持重试或返回 | 把失败显示成成功、自动重复写入 |
| 部分成功 | 明确成功/失败数量和失败对象，提供错误行或后续处理入口 | 只显示总数或笼统“部分失败” |
| 无权限 | 说明当前身份和允许范围；隐藏敏感内容但保留返回路径 | 先显示数据再报错 |
| 只读/归档 | 显示明显状态和原因，写按钮禁用或移除 | 按下写按钮后才提示不能修改 |
| 提交中 | 锁定本次提交、显示进度或阶段；允许安全取消时提供取消 | 重复点击产生多次写入 |
| 离线/依赖不可用 | 说明受影响功能和仍可使用的本地能力 | 让整个工作台不可用 |

## 3. 响应式、可访问性和性能

### 3.1 验证尺寸

每个主要页面至少验证：

- Electron 主窗口：`1280×820`。
- 窄桌面/平板：`768×1024`。
- 局域网手机：`390×844`，并考虑安全区。

现有主窗口最小宽度不代表手机页面可以忽略；手机访问使用相同前端构建。

### 3.2 响应式规则

- 桌面双栏在手机上改为顺序明确的单栏或分步流程，不把两栏压缩成两个极窄区域。
- 表格在手机上优先转为摘要行 + 展开详情；课程表等确需保持二维关系的内容才允许有提示的横向滚动。
- 手机端点击目标不低于 44px，标题栏操作可换行或进入底部固定操作区。
- 弹窗在手机端改为底部面板或全屏步骤页，长表单不能困在小高度浮层内。
- 固定按钮、Agent 浮窗、系统安全区和桌面宠物不能互相遮挡。

### 3.3 可访问性

- 输入控件有真实 label；图标按钮有 `aria-label` 和可见 tooltip。
- 错误、成功、选中、逾期和风险不能只靠颜色表达。
- 键盘 Tab 顺序与视觉顺序一致；弹窗打开后聚焦内部，关闭后焦点返回触发按钮。
- 复制、上传、拖拽和排序必须有不依赖拖拽的替代操作。
- 遵循 `prefers-reduced-motion`，重要状态不能只通过动画传达。
- 中文正文不低于现有设计系统的 14px，辅助信息不低于 12px。

### 3.4 性能

- 列表和图片先加载摘要/缩略图，详情按需读取。
- 搜索输入做合理节流；筛选和排序不触发无界请求。
- 页面隐藏、宠物隐藏或屏幕锁定时暂停非必要动画和轮询。
- 不因一个首页卡片启动新的高频轮询；优先复用已有首页数据请求。

## 4. 各工作包界面合同

### 4.1 SUP-01：微信现场操作

主要界面是微信对话，不新增网页导航。每一轮只要求用户做一个决定：选择班级、补充异常、核对预览或确认写入。

- 选择项保持短小；班级过多时先按年级筛选，不发送全校长列表。
- 写入预览固定显示班级、日期、场景、总人数和异常名单。
- “确认写入”和“取消”使用明确文字；过期后不继续沿用旧预览。
- 成功消息显示写入/更新数量，失败消息说明没有写入还是部分写入。
- 网页考勤页继续承担批量查看和修正，微信不模拟完整表格。

### 4.2 SUP-02：对话式 Excel 导入

入口使用现有 Agent。浮窗支持选择文件和查看摘要，复杂流程进入 `/agent` 完整页。

完整页按四段显示：

1. 文件：文件名、大小、工作表和移除按钮。
2. 识别：候选模块、班级/学期和需要补充的问题。
3. 预览：字段映射、有效/错误/新增/更新/跳过数量和错误行。
4. 提交结果：实际写入数量、失败行下载和返回业务页面。

预览阶段使用稳定的步骤状态，不用无限聊天气泡堆叠表格。手机端先展示数量和关键错误，详细映射表提示到桌面完整页查看。

识别区同时显示“AI 语义识别 + 本地规则校验”或“本地规则识别”，模型不可用时用一行非阻断提示说明已安全回退。候选项必须同时写出模块与工作表，避免同一模块存在多个候选工作表时误选；字段映射状态区分“规则匹配”和“AI 建议，已校验”。

### 4.3 SUP-03：首页考试倒计时

在首页“今日课程”附近增加一张横向的“近期考试”卡，不向顶部四项行动摘要继续增加第五个等宽卡片。

- 左侧突出下一场考试名称、日期和倒计时。
- 右侧最多列出后续两场考试，显示班级/科目标签。
- 无考试时使用紧凑空状态和“前往考试设置”入口。
- 已结束考试不继续占据首页；日期缺失显示“待补日期”，不显示倒计时。
- 手机端上下排列，倒计时数字不挤压考试名称。

### 4.4 SUP-04：多班级教师视角

优先在 `/timetable` 增加“单班课表 / 我的安排”分段视图。多班视图默认使用按日期分组的议程列表，而不是把多个班级叠在一张彩色周课表上。

- 顶部显示“我的班级”筛选，每项始终写班级名称；颜色只作辅助。
- 议程行显示时间、班级、科目、教室和考试/调课状态。
- 桌面可提供周视图切换，但同一时段冲突必须有文字标识。
- 手机只使用议程列表，不展示多班叠加周网格。
- 从汇总项进入写入动作时切回明确单班级上下文并再次显示范围。

### 4.5 SUP-05：统一工作入口

新增 `/tools`，侧边栏只增加一个“工作入口”。

- 顶部是搜索和“新增入口”主按钮。
- 第一段显示少量置顶入口，后续按分类列出；最近使用是排序信号，不再增加独立大模块。
- 每个入口显示名称、域名和分类；图标加载失败时有稳定占位。
- 编辑使用现有弹窗模式，URL 校验错误靠近输入框。
- 手机端使用单列列表；外链点击后明确交由系统浏览器打开。

### 4.6 SUP-06：AI 家校通知与家长消息回复

将现有 `/parent-comm` 组织为“沟通记录 / AI 通知 / AI 会谈”三个页内视图，侧边栏继续只有“家校沟通”。

AI 通知桌面采用双栏：左侧通知类型与关键信息，右侧 AI 生成的可编辑微信文案和复制操作。后端可以使用结构化场景定义校验事实，但界面不向教师暴露“模板”概念。右侧不是手机外观装饰，而是可读、可编辑的正文工作区。

- 场景卡片数量较多时按类别筛选，不把所有卡片同时铺开。
- 必填信息在生成前集中显示，字段名与必填星号保持同行，错误靠近字段。
- 文案区明确标注“草稿”，复制后提示“已复制，尚未证明已发送”。
- 当前不提供个人模板的创建、选择和管理入口，所有通知都从通知类型进入并由 AI 生成。
- 手机端改为“选类型 → 填信息 → 编辑复制”三步，不保持左右双栏。

沟通台账标题区增加“回复家长”次级按钮，进入聚焦式回复工作区时临时隐藏页内分段导航，并提供返回沟通记录入口，不新增第四个常驻页签。

- 桌面端采用左侧输入、右侧结果的双栏；手机端改为单列。左侧只收学生、教师角色、家长原话、教师已知情况和折叠的后续安排。
- 右侧先显示处置等级、已确认输入和待核实信息，再显示可编辑回复；系统事实、核实问题和权限边界默认折叠。
- 处置等级只使用“可直接回复 / 核实后回复 / 建议升级处理”，不能使用缺少依据的概率、分数或红绿滑杆。
- 处置等级下方显示教师内部使用的“制度边界辅助判断”：分别呈现可能涉及的制度要求、原文证据及状态、待核实条件、投诉升级信号和建议处置；明确标注“辅助判断，不构成法律结论”。
- “未出现投诉升级信号”不等于“事项没有合规风险”；页面必须把两者分开，避免只靠投诉关键词判断。
- 语气切换只改变表达方式，不改变规则分流、家长原话或系统事实。
- “复制回复”不代表已经发送；只有教师点击“已发送，保存记录”并再次确认后，才进入沟通台账和回访闭环。
- 原始截图上传与沟通记录创建绑定；当前不显示 OCR 已识别之类的误导状态。

### 4.7 SUP-07：家长会/个别谈话准备

入口放在 `/parent-comm` 的“AI 会谈”视图，也可从学生详情以带学生 ID 的深链接进入。桌面和手机共享同一条流程，不再拆成两套步骤状态。

- 左侧只保留学生、会谈目的、可选关注点和一个“AI 准备会谈”主操作；日期范围与事实类别收在“资料范围”高级选项中。
- 默认资料范围为当前学期开始至业务当天，截止日期不能超过当天；所有类别使用同一组筛选条件生成事实和 AI 方案。
- 结果依次展示会谈重点、值得肯定、需要关注、待核实问题、建议开场、沟通要点、后续行动和可编辑完整提纲。
- AI 的优势和关注点必须关联可核对的事实编号；事实依据单独折叠展示，并使用面向教师的来源名称和日期，不能暴露数据库表名。
- “暂无记录”只表示所选范围内缺少记录，不推断为表现正常；手机号、住址等敏感字段不进入页面专用 AI 上下文。
- 当前未接入健康事实时不显示健康选项；复制只针对教师确认后的提纲，生成和取消都不会保存教育记录。
- 模型不可用或返回不可解析内容时保留事实摘要并明确提示，不把失败伪装成已生成结果。

### 4.8 SUP-08：图片/截图证据

证据作为相关记录详情中的标准区块，不先建设全局图片库。

- 列表行显示回形针、数量和“有凭证/待补凭证”，不加载原图。
- 详情区加载缩略图、类型、说明、来源和上传时间。
- 上传支持选择、粘贴和手机拍照；确认前展示本地预览和关联对象。
- 删除入口在单张图片菜单内，必须填写原因；删除后保留历史提示。
- 原图查看使用受保护的预览层，提供下载和关闭；手机支持双指缩放时不能妨碍关闭。

### 4.9 SUP-09：桌面宠物

宠物是独立透明窗口，视觉和交互细节以主清单 `SUP-09` 为准。

- 设置入口放在桌面设置和托盘，不进入业务侧边栏。
- 气泡使用设计系统的表面、字体和状态色，宽度受控，不显示长错误。
- 角色动画是品牌表达；主工作台仍是唯一业务操作面。
- 宠物开启后不得遮挡 Agent 浮窗、系统任务栏/Dock 或主窗口的关键操作。

## 6. 防止界面膨胀的规则

- 每个 `SUP-xx` 先解决一个主要工作流；次要统计和高级设置在真实需要出现后再加。
- 首页只增加高频、当天相关的信息；管理、配置和历史留在对应页面。
- 新模块优先扩展已有页面的页内视图，导航变化必须在任务开始前明确。
- 同一状态只使用一种标签和一种术语，不能在不同页面出现“已完成/完成/成功”三套近义状态。
- 不因 Agent 能生成内容就增加大面积聊天式 UI；结构化任务使用结构化表单、预览和结果。
- 不为每个工作包新增专用颜色、圆角、阴影或弹窗组件；优先使用现有 token 和共享组件。
- 桌面宠物、AI 通知和 Agent 动效承担适量个性表达，成绩、考勤、证据和权限界面保持克制可靠。
